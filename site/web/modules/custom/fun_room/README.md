# Fun room

Rooms and participants for the Fun-o-Meter. Attendees join a room with a code;
the Join component (`fun-canvas-project`, and the standalone `prototype/`) talks
to this module through core JSON:API, and every room has a page rendered by one
Canvas template.

## What it provides

- **Room** is a node of type `room`. The title is the room code (stored trimmed
  and uppercase, and unique among rooms). Fields: `field_status` (`open` or
  `closed`), `field_current_slide` (zero-based index) and
  `field_current_slide_id`. Pathauto serves each room at `/room/<code>`, for
  example `/room/ned-4261`. Rooms are not content-moderated; a room is just open
  or closed.
- **Participant** (`fun_participant`, a custom entity): `room` (reference to a
  room node), `name` (1-30 characters), `avatar` (0-5) and a write-only `token`.
  Only the token's SHA-256 is stored (`token_hash`); the secret is generated by
  the client and never readable.
- **Access:** anyone can read published rooms and create a participant (the
  `join fun room` permission, granted to anonymous and authenticated users on
  install). Everything else, including reading participants, needs
  `administer fun_room`; creating or editing rooms is ordinary node access.
- **Rate limit:** 30 joins per 5 minutes per IP, then HTTP 429.
- **On install** the module enables JSON:API writes (`jsonapi.settings:
  read_only: false`; core ships JSON:API read-only) and takes `room` out of
  Drupal CMS's editorial workflow, which would otherwise keep every new room an
  unpublished draft (a 404 for attendees).
- All of the module's config is marked as enforced by the module, so Drupal can
  remove it with the module. (Uninstalling is not covered by the tests.)

## Local setup

From `site/`, with DDEV running:

```bash
ddev drush en fun_room -y
ddev drush fun-room:create NED-4261
```

### CORS for local clients (not in git)

Canvas pages served by Drupal are same-origin and need nothing. The standalone
prototype, the slide deck and Canvas Workbench run on other localhost ports, so
the browser blocks their calls unless Drupal allows those origins.

Create `site/web/sites/default/services.yml` (it is gitignored by
`site/.gitignore`, so a fresh checkout must recreate it):

```yaml
parameters:
  cors.config:
    enabled: true
    allowedHeaders: ['Content-Type', 'Accept', 'Authorization']
    allowedMethods: ['GET', 'POST', 'OPTIONS']
    allowedOrigins: []
    allowedOriginsPatterns: ['#^http://localhost:\d+$#', '#^http://127\.0\.0\.1:\d+$#']
    exposedHeaders: false
    maxAge: false
    supportsCredentials: false
```

Then `ddev drush cr`. If the file already exists, merge the `cors.config` block
into it. Drupal only loads `services.yml`, not `default.services.yml`. CORS
applies to the whole site, not just `/jsonapi`. Production origins are a deploy
decision, so do not copy these localhost patterns there.

Check it from a terminal (expect `access-control-allow-origin` in the output):

```bash
curl -sk -i -X OPTIONS https://fun-canvas-code.ddev.site/jsonapi/fun_participant/fun_participant \
  -H 'Origin: http://localhost:5173' -H 'Access-Control-Request-Method: POST' \
  | grep -i access-control
```

## API

Look up a room by code (an empty `data` array means no such room). The response
includes `field_status`, `field_current_slide` and `path.alias`:

```bash
curl -sk -g 'https://fun-canvas-code.ddev.site/jsonapi/node/room?filter[title]=NED-4261' \
  -H 'Accept: application/vnd.api+json'
```

Read one room by its JSON:API id (this is what the room page polls):
`GET /jsonapi/node/room/{uuid}`.

Join: `POST /jsonapi/fun_participant/fun_participant` with
`Content-Type: application/vnd.api+json`. The `token` must be 16-128 characters
and `relationships.room` is the room's JSON:API `id` from the lookup above:

```json
{
  "data": {
    "type": "fun_participant--fun_participant",
    "attributes": { "name": "Sam", "avatar": 2, "token": "<secret, 16-128 chars>" },
    "relationships": {
      "room": { "data": { "type": "node--room", "id": "<room uuid>" } }
    }
  }
}
```

| Result | Meaning |
|---|---|
| 201 | Joined. The response never includes the token. |
| 422 | Invalid name, avatar or token, or the room is closed (pointer `/data/attributes/room`). |
| 403 | Not allowed, for example reading or changing a participant anonymously, or creating a room. |
| 429 | Too many joins from this IP. |

## Managing rooms

Rooms are ordinary content. In the admin sidebar use **Create > Room** to add
one, or **Fun rooms** (the Content list filtered to rooms) to see them. Set
**Status** to Closed to stop new joins; people already in the room are
unaffected. **Fun participants** lists who joined, newest first. Deleting a room
does not delete its participants.

From the command line (both accept any case; the code is stored uppercase):

```bash
ddev drush fun-room:create NED-4261   # create, or reopen if it exists; prints the room path
ddev drush fun-room:close NED-4261
```

Use a new code for each event; there is no "reset room" action.

## Room page (one Canvas template for every room)

Canvas content templates only support nodes in Canvas 1.12, which is why rooms
are nodes. `fun-canvas-project/content-templates/node.room.full.json` is the
single template: it renders every room node with the `room` component (code,
open/closed status, current slide, polled every 2 seconds) and a `placeholder`
in each of its four slots (`swarm`, `slider`, `requests`, `comments`). When a
feature's backend lands, build its component and replace that slot's placeholder
in the template; `room` does not change.

From `fun-canvas-project/`:

```bash
npm run canvas -- validate
npm run canvas -- push --no-pages --no-page-templates --no-include-brand-kit -y
```

The template is enabled by the push. A visitor who has not joined that room in
this browser sees a "Join this room" link to `/?code=<code>`; the home page's
Join component sends anyone who has joined straight to their room.

## Tests

Functional tests use `drupal/core-dev`. From `site/`:

```bash
ddev exec 'mkdir -p /tmp/bto && SIMPLETEST_BASE_URL=http://localhost SIMPLETEST_DB=mysql://db:db@db/db BROWSERTEST_OUTPUT_DIRECTORY=/tmp/bto vendor/bin/phpunit -c web/core web/modules/custom/fun_room'
```

Expect `OK, but there were issues!`: the deprecation notices come from other
modules, not this one.
